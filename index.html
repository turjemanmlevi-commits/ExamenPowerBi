Power BI · Exam cheat sheet

Mock 1 TechCart + Mock 2 Meridian. Every code block copies with one click. Anything in yellow inside the code is one of your table or column names: change it once in the “My names” panel and every snippet updates.

Exam order: what to do and when

  1. Read the brief and write down the 4 topicsThey tell you what to analyse. That decides which columns you must NOT delete (e.g. ratings) and which measures you need.
  2. Get data → Transform data (Power Query): cleanRemove Top Rows → Headers → Remove columns → Replace Values → Change Type → Split/Unpivot. Types always before creating columns.
  3. Append / Merge if there are several filesAfter cleaning each query (same names and types), before creating calculated columns on the result.
  4. New columns (Custom / Conditional)At the end of Power Query. Set their type straight away. Then filters, Enable Load off on source queries, and Close & Apply.
  5. Date tableOutside Power Query, once the Date types are set. Create → Mark as date table → Sort by column.
  6. Relationships (Model view)From the dimension to the fact, 1:*, Single. Including Date[Date] → your date column.
  7. _Measures table and measuresBasics first (Total Sales, Total Orders), then ratios and time intelligence, which depend on them. $ / % format.
  8. Visuals, one block per topicFirst get them ALL on the page, even if ugly. Then polish.
  9. Output: theme, slicers, navigation, bookmarks, captionsScores points and gets forgotten.
  10. Final checklist (5 min)Save the .pbix before and after.
If something breaks and time is short: make sure everything is present, even unpolished. A missing part scores zero; a part that is there with a default title scores almost everything.
1

Cleaning in Power Query — the right order

When: first thing, right after loading the data (Home → Transform data). Before the date table, relationships or measures.

The order

  1. Remove Top Rows (junk rows above the headers)
  2. Use First Row as Headers
  3. Remove columns (keep only the ones you use: the brief asks for it)
  4. Replace Values (USD, $, typos, double spaces)
  5. Change Type
  6. Split / Unpivot
  7. Calculated columns (Custom / Conditional)
  8. Filters
Types ALWAYS before creating calculated columns. If price is text, the formula errors or comes out as Text, and later SUM returns blank.
See nulls and errors at a glance: View → Column quality / Column distribution.

Traps

What you seeWhat to do
"USD 94.70" in a numeric columnReplace Values: USD (with the space) → nothing. Then Decimal Number.
"$45" mixed with 45Replace Values: $ → nothing. Then a numeric type.
Columns whose name is a date (2025-01, 2025-02…)Select the text/ID columns that stay fixed → right-click → Unpivot Other Columns. Rename Attribute / Value.
Text date "2025-01" (no day)Add Column → Custom Column with the formula below → Date type.
dd/mm/yyyy converts wronglyChange Type → Using Locale → Date → English (United Kingdom).
Double spaces / leftover spacesReplace Values (2 spaces → 1) + Transform → Format → Trim.
"0nline" / "Inst0re" (zero instead of O)Replace Values + tick Match entire cell content (under Advanced options).
Fully duplicated rowsSelect ALL columns → Remove Rows → Remove Duplicates.
Duplicate ID in a dimension (breaks 1:*)Sort by date descending → select ONLY the ID column → Remove Duplicates (keeps the most recent).
Amounts in several currenciesCustom Column: value × exchange rate (formula below).
Date.FromText(⟦m:datecol⟧ & "-01")
⟦m:amount⟧ * ⟦m:rate⟧
After any Custom Column: set its type (Date, Decimal Number…). It comes out as ABC123 (type Any) and ends up as text in the model.

Missing values (nulls)

The brief says: if a column has many nulls, delete the COLUMN, not the rows.

But if that column is one of the topics you are asked to analyse, do NOT delete it: AVERAGE ignores blanks on its own.

Enable Load and query order

When: just before Close & Apply, once you have your final queries.

  • Right-click each source query (the ones that only feed an Append/Merge) → untick Enable load. They turn italic.
  • Group them: right-click → Move to group → Source Queries / Report Queries.
2

Append and Merge Queries

When: in Power Query, after cleaning each query on its own (same headers, names and types) and before creating calculated columns on the result.

Which one do I need?

SituationUse
Two files with the same structure (sales 2024 + sales 2025, store A + store B)Append → stacks rows. The table grows downwards.
I want to bring columns from another table using a key (actuals + budget, exchange rate per currency)Merge → joins columns. The table grows to the right.
A lookup table (countries, products, cost centres) I only use to filter or groupNeither: leave it as a dimension and create a 1:* relationship. That is what the star schema wants.

Append — stack rows

  1. In each query: same headers (exact same name, capitals included) and same types.
  2. If you later need to know which file each row came from: before appending, Add Column → Custom Column in each one, e.g. "2024".
  3. Home → Append Queries ▾ → Append Queries as New (creates a new query, leaves the originals alone).
  4. Two tables (or Three or more tables) → pick the queries → OK.
  5. Rename the new query and untick Enable load on the two sources.
= Table.Combine({⟦q:qa⟧, ⟦q:qb⟧})
ProblemCause and fix
Half-empty duplicated columns appear (Price and price)The names do not match. Rename in the sources so they are identical.
The stacked column is ABC123Different types in each source. Set the type again in the new query.
Did it work?Rows in the result = sum of the rows in the sources (bottom left, or Transform → Count Rows).

Merge — bring columns from another table

  1. Check that the key column has the same type in both queries and is clean (Trim, no typos).
  2. Select the main query (the one you want to keep whole) → Home → Merge Queries ▾ → Merge Queries as New. (Plain Merge Queries adds the columns to the current query.)
  3. Click the key column in the top table, choose the second table below and click its key column.
    Several key columns: Ctrl+click in the same order in both tables (small numbers 1, 2, 3 appear and must match).
  4. Join Kind: Left Outer (all rows from the first, whatever matches from the second).
  5. Read the message at the bottom: "The selection matches X of Y rows". If X is very low, the keys do not match (type, spaces, capitals).
  6. OK → on the new column (it says Table) click the expand icon (two arrows) → tick only the columns you want → untick "Use original column name as prefix" → OK.
  7. Set the type of the expanded columns and untick Enable load on the sources.
= Table.NestedJoin(⟦q:qa⟧, {"⟦key⟧"}, ⟦q:qb⟧, {"⟦key⟧"}, "⟦qb⟧", JoinKind.LeftOuter)
= Table.ExpandTableColumn(#"Merged Queries", "⟦qb⟧", {"⟦budcol⟧"}, {"⟦budcol⟧"})
Join KindWhat it returns
Left Outer (the usual one)All rows from the 1st + whatever matches from the 2nd. No match → null.
InnerOnly rows that exist in both.
Full OuterAll rows from both, matched or not.
Left AntiRows from the 1st with NO match. Handy for finding which rows fail.
ProblemCause and fix
All null after expandingKeys with different types (text vs number) or with spaces. Match the type + Trim in both and repeat.
MORE rows after the merge than beforeThe 2nd table has duplicated keys. Remove duplicates there before merging.
Columns named "Budget.cost_center_code"You left the prefix ticked. Delete the Expanded step and redo it.
Nulls in just a few rowsNormal when one table has rows the other lacks (Mock 2: actuals has 2 more than budget). Do not delete them, comment on it.

When I add a new column

When: at the end of Power Query, with types set and Append/Merge done. After creating it: type → Close & Apply → measure → format.

Column or measure? Decide first

I need…Build it as
A value per row: amount = quantity × price, convert to USD, a label (Miss/Meet, High/Low)Power Query column (Custom or Conditional). This is what the notes use.
A per-row value that needs another model table or a measureDAX calculated column (Table tools → New column) with RELATED.
A total, average, ratio or % that must react to slicersMeasure. Never a % as a column: the average of percentages gives a wrong answer.
I want it in a slicer, axis or legendIt has to be a column (a measure cannot go in a slicer).

The steps, always the same

  1. Check the columns you will use have the right type (123 / 1.2, not ABC).
  2. Add Column → Custom Column (formula) or Add Column → Conditional Column (if/else without typing).
  3. Set the type of the new column (it comes out as ABC123): Decimal Number, Whole Number, Text or Date.
  4. Home → Close & Apply.
  5. In the Data pane look at the icon: Σ = number, no icon/ABC = text.
  6. Create the measures on the column (do not drag the raw column: you would get "Sum of…").
  7. If it is a category with a logical order (Low/Medium/High), create its order column and apply Sort by column.

Custom Column — formulas to paste

In the Custom Column box do not type the name or the «=»: the name goes in the field above. Double-clicking a column in the list on the right inserts it correctly spelled.

⟦m:qty⟧ * ⟦m:price⟧
⟦m:qty⟧ * ⟦m:price⟧ * (1 - ⟦m:disc⟧)
⟦m:actcol⟧ - ⟦m:budcol⟧
⟦m:amount⟧ * ⟦m:rate⟧
If the discount has nulls, the discount formula returns null on those rows. Use this version:
⟦m:qty⟧ * ⟦m:price⟧ * (1 - (if ⟦m:disc⟧ = null then 0 else ⟦m:disc⟧))

Conditional Column (no M typing)

  1. Add Column → Conditional Column → type the name in New column name.
  2. If row: Column Name (the one you test) · Operator (is less than, equals…) · Value · Output.
  3. Add Clause for each extra condition (these are the else ifs).
  4. Else: the value for everything else.
  5. OK → set the type (nearly always Text).
It is evaluated top to bottom: the first condition that is true wins, so "< 10" goes before "< 20".
In Output, the selector on the left must be on Value (ABC123), not on "Select a column". Same for the Value box of the condition.

The same thing typed by hand in Custom Column (faster when you already have it here):

if ⟦m:basecol⟧ < 0 then "Miss" else "Meet"
if ⟦m:basecol⟧ < 10 then "Low"
else if ⟦m:basecol⟧ < 20 then "Medium"
else "High"
if ⟦m:basecol⟧ = null then "No data"
else if ⟦m:basecol⟧ < 10 then "Low"
else if ⟦m:basecol⟧ < 20 then "Medium"
else "High"
if ⟦m:flagcol⟧ = ⟦v:flagval⟧ then 1 else 0
if ⟦m:basecol⟧ >= 10 and ⟦m:flagcol⟧ = ⟦v:flagval⟧ then "Yes" else "No"
M rules: if then else in lowercase, always needs else, text in double quotes, case-sensitive ("Yes" ≠ "yes"). Comparing a null with < or > errors: that is why null is checked first.

Order column so Low/Medium/High do not sort alphabetically (Whole Number type; then in the report: select the text column → Column tools → Sort by column → this one):

if ⟦m:newcol⟧ = "Low" then 1
else if ⟦m:newcol⟧ = "Medium" then 2
else 3

The same as a DAX calculated column extra

When: you already closed Power Query and do not want to go back, or you need data from a related table. Table view → select the table → Table tools → New column.

Line Total = ⟦t:fact⟧[⟦qty⟧] * ⟦t:fact⟧[⟦price⟧]
⟦newcol⟧ = IF(⟦t:fact⟧[⟦basecol⟧] < 0, "Miss", "Meet")
⟦newcol⟧ =
SWITCH(TRUE(),
    ISBLANK(⟦t:fact⟧[⟦basecol⟧]), "No data",
    ⟦t:fact⟧[⟦basecol⟧] < 10, "Low",
    ⟦t:fact⟧[⟦basecol⟧] < 20, "Medium",
    "High"
)
⟦dimcol⟧ = RELATED(⟦t:dim⟧[⟦dimcol⟧])
In DAX it is IF() in capitals with commas; in M it is if then else in lowercase. They do not mix.

Measures on the new column

In “My names” → New column type your column name and the value you want to count. Select the _Measures table → New measure → paste one at a time.

Total ⟦newcol⟧ = SUM(⟦t:fact⟧[⟦newcol⟧])
Avg ⟦newcol⟧ = AVERAGE(⟦t:fact⟧[⟦newcol⟧])
Num ⟦newval⟧ = CALCULATE(COUNTROWS(⟦t:fact⟧), ⟦t:fact⟧[⟦newcol⟧] = ⟦v:newval⟧)
% ⟦newval⟧ = DIVIDE([Num ⟦newval⟧], COUNTROWS(⟦t:fact⟧))
⟦mSales⟧ ⟦newval⟧ = CALCULATE([⟦mSales⟧], ⟦t:fact⟧[⟦newcol⟧] = ⟦v:newval⟧)
Afterwards: Measure tools → Format ($, %, decimals). To see the split by category you do not need a new measure: put the column on the axis and your base measure in values.

Date table

When: AFTER Close & Apply, with the date columns already typed as Date. Before relationships and any time-intelligence measure.

Create the table

Table view → Home (or Table tools) → New table. Paste:

⟦dateT⟧ =
ADDCOLUMNS (
    CALENDARAUTO( ),
    "Year", YEAR ( [Date] ),
    "Month Name", FORMAT ( [Date], "mmmm" ),
    "Month Number", MONTH ( [Date] ),
    "Day", DAY( [Date] ),
    "Day of Week", FORMAT ( [Date], "ddd" ),
    "Day of Week No", WEEKDAY( [Date],2 )
)

PLAN B (always works): swap the CALENDARAUTO line for an explicit range.

⟦dateT⟧ =
ADDCOLUMNS (
    CALENDAR( DATE(2015,1,1), DATE(2025,12,31) ),
    "Year", YEAR ( [Date] ),
    "Month Name", FORMAT ( [Date], "mmmm" ),
    "Month Number", MONTH ( [Date] ),
    "Day", DAY( [Date] ),
    "Day of Week", FORMAT ( [Date], "ddd" ),
    "Day of Week No", WEEKDAY( [Date],2 )
)
⟦dateT⟧ =
ADDCOLUMNS (
    CALENDAR(
        DATE( YEAR( MIN( ⟦t:fact⟧[⟦datecol⟧] ) ), 1, 1 ),
        DATE( YEAR( MAX( ⟦t:fact⟧[⟦datecol⟧] ) ), 12, 31 )
    ),
    "Year", YEAR ( [Date] ),
    "Month Name", FORMAT ( [Date], "mmmm" ),
    "Month Number", MONTH ( [Date] ),
    "Day", DAY( [Date] ),
    "Day of Week", FORMAT ( [Date], "ddd" ),
    "Day of Week No", WEEKDAY( [Date],2 )
)

Afterwards, ALWAYS (3 things)

  1. Table selected → Table tools → Mark as date table → Date column.
    Without this DATEADD, SAMEPERIODLASTYEAR, TOTALYTD and the Forecast do not work.
  2. Sort months: click Month Name → Column tools → Sort by column → Month Number. Same for Day of Week by Day of Week No.
  3. Model view: relationship Date[Date] → your date column (1:*).
At the very end: File → Options → Current File → Data Load → untick Auto date/time (once you are using your own Date table).

Model — star schema

When: after the date table and before the measures. If measures show the same total on every bar, come back here.

Create relationships

Model view. Drag from the DIMENSION to the FACT. Cardinality One to many (1:*) with the 1 on the dimension. Cross filter Single.

Quick test: a table visual with one dimension field + one measure. Do the values change per row? Then the relationship works.

Typical problems

SymptomCause and fix
All bars equal / same total repeatedTHE RELATIONSHIP IS MISSING. Create it in Model view.
It rejects 1:* and proposes Many-to-manyThe dimension has duplicate IDs. Remove them in Power Query. NEVER accept many-to-many.
"Ambiguous paths between tables"Untick Make this relationship active → it becomes a dotted line. That is correct.
It will not let you create the relationshipDifferent types (text vs number). Make them equal in Power Query.
(Blank) in slicers or chartsFact rows with no match in the dimension. Filter on the visual: Advanced filtering → is not blank.

Inactive relationship, to use it now and then

Sales by Release = CALCULATE([Total Sales],
  USERELATIONSHIP('Date'[Date], Prod[Release Date]))

Swap Prod[Release Date] for the date column on the dotted-line relationship. An adaptable version is in Relationships.

Relationships — which table goes to which

When: Model view, right after the Date table. One relationship per dimension, all pointing at the fact table.

The one rule

The table where the key is UNIQUE (one row per ID) is the “1” side. The table where the key REPEATS is the “*” side. The 1 side is the dimension (lookup); the * side is the fact (transactions). The filter arrow points from 1 to *.

Dimension · key is unique · 1product_sustainability[product_id]1 ───▶ *Fact · key repeats · *orders[product_id]
“One to many (1:*)” and “Many to one (*:1)” are the same relationship. The dialog just names it after whichever table is listed first. What matters: the 1 sits next to the dimension and Cross filter direction says Single.

Which one is the dimension? 10-second test

  • Row count: the small table (35, 57, 95 rows) is the dimension; the big one (174, 9,000 rows) is the fact.
  • Uniqueness: Power Query → click the key column → View → Column distribution. If it says “95 distinct, 95 unique” and the table has 95 rows, the key is unique → 1 side.
  • Find the offenders: select the key column → Home → Keep Rows → Keep Duplicates. Empty result = unique. Then delete that step in Applied Steps.
  • Meaning: does the table describe things (a product, a country, a cost centre, a day)? Dimension. Does it record events or amounts (orders, expenses)? Fact.

Relationship helper

Fill this in for the two tables you want to connect and it tells you what to do.

Every case you can meet

CaseWhich goes to which
Lookup → fact (products, countries, cost centres)lookup[key] 1 → * fact[key]. Single. This is 90% of the exam.
Date table → factDate[Date] 1 → * fact[date column]. The fact column must be type Date (not text, not Date/Time with hours — otherwise nothing matches).
Fact with two date columns (order date + ship date)Date[Date] → first date: active. Date[Date] → second date: inactive (dotted). Use it with USERELATIONSHIP (below).
Lookup that only covers some keys (score for 95 of 150 products, audit for 35 of 57 centres)Still lookup[key] 1 → * fact[key]. The uncovered rows show as (Blank). Expected: filter it out or comment on it.

Creating it, click by click

  1. Fast way: Model view → drag the key column from the dimension and drop it on the matching column of the fact.
  2. Safe way: Home → Manage relationships → New → top dropdown: the dimension, click its key column → bottom dropdown: the fact, click its key column.
  3. Check Cardinality: One to many (1:*) — or Many to one (*:1) if you listed the fact first.
  4. Check Cross filter direction: Single.
  5. Make this relationship active: ticked (unless it is the second date relationship).
  6. OK → in the diagram the 1 must sit next to the dimension and the * next to the fact.
  7. Power BI may have auto-created relationships on load: open Manage relationships and delete any wrong one first.
Before you blame the relationshipCheck
Keys are text vs numberSet the same type on both sides in Power Query.
Keys have stray spacesTransform → Format → Trim (and Clean) on both sides.
Date key has a time partChange type to Date (not Date/Time).
Blank row in the dimension keyFilter out null in the dimension, otherwise it counts as a duplicate/blank key.
Final test: table visual with a dimension field + [your base measure]. Different value on each row = working. Same value everywhere = relationship missing or on the wrong column.
7

Measures

When: once relationships exist. Order: _Measures table → basics → count with a condition → ratios → time intelligence. Later ones use earlier ones, so paste them in this order.

First: the _Measures table

  1. Home → Enter data → name _Measures → Load (empty table).
  2. Select it in the Data pane before every New measure.
  3. Paste ONE measure at a time and press Enter.
If the bar says "Date Table =" or "Date =", press Esc: you are overwriting the table, not creating a measure.

Basics

⟦mSales⟧ = SUMX(⟦t:fact⟧,
   ⟦t:fact⟧[⟦qty⟧] * ⟦t:fact⟧[⟦price⟧])
⟦mSales⟧ = SUMX(⟦t:fact⟧, ⟦t:fact⟧[⟦qty⟧] *
  ⟦t:fact⟧[⟦price⟧] * (1 - ⟦t:fact⟧[⟦disc⟧]))
⟦mSales⟧ = SUM(⟦t:fact⟧[⟦amount⟧])
Total Orders = DISTINCTCOUNT(⟦t:fact⟧[⟦orderid⟧])
Total Customers = DISTINCTCOUNT(⟦t:fact⟧[⟦custid⟧])
Total Quantity = SUM(⟦t:fact⟧[⟦qty⟧])
Average Rating = AVERAGE(⟦t:fact⟧[⟦rating⟧])
AOV = DIVIDE([⟦mSales⟧], [Total Orders])
DISTINCTCOUNT, not COUNT: one order spans several rows. DIVIDE, not "/": avoids the divide-by-zero error.

Count with a condition

Num Returns = CALCULATE(COUNTROWS(⟦t:fact⟧),
                ⟦t:fact⟧[⟦flagcol⟧] = ⟦v:flagval⟧)
Score⟦dimval⟧ = CALCULATE(COUNTROWS(⟦t:dim⟧), ⟦t:dim⟧[⟦dimcol⟧] = ⟦v:dimval⟧)
Numbers without quotes, text with quotes. If you get 0 or blank, look at the column icon: Σ = number, ABC = text. (Here the quotes are added automatically from what you type in “My names”.)

Ratios and variance

Return Rate = DIVIDE([Num Returns], COUNTROWS(⟦t:fact⟧))
% of Total = DIVIDE([⟦mSales⟧],
   CALCULATE([⟦mSales⟧], ALL(⟦t:fact⟧)))
% of Selected = DIVIDE([⟦mSales⟧],
   CALCULATE([⟦mSales⟧], ALLSELECTED()))
Total Actuals = SUM(⟦t:fact⟧[⟦actcol⟧])
Total Budget = SUM(⟦t:fact⟧[⟦budcol⟧])
Variance = [Total Actuals] - [Total Budget]
Variance % = DIVIDE([Variance], [Total Budget])

Time intelligence

Requires Mark as date table + the Date[Date] → your date relationship + using fields from the Date table in the visuals (not the date from the fact table).
⟦mSales⟧ LY = CALCULATE([⟦mSales⟧],
   SAMEPERIODLASTYEAR(⟦t:dateT⟧[Date]))
YoY % =
VAR Cur = [⟦mSales⟧]
VAR Prior = CALCULATE([⟦mSales⟧],
   DATEADD(⟦t:dateT⟧[Date], -1, YEAR))
RETURN DIVIDE(Cur - Prior, Prior)
⟦mSales⟧ YTD = TOTALYTD([⟦mSales⟧], ⟦t:dateT⟧[Date])
⟦mSales⟧ PM = CALCULATE([⟦mSales⟧],
   DATEADD(⟦t:dateT⟧[Date], -1, MONTH))
MoM % = DIVIDE([⟦mSales⟧] - [⟦mSales⟧ PM], [⟦mSales⟧ PM])

Filter inside CALCULATE

High Score Sales = CALCULATE([⟦mSales⟧],
   FILTER(⟦t:dim⟧, ⟦t:dim⟧[⟦dimcol⟧] >= 2))
⟦mSales⟧ Filtered = CALCULATE([⟦mSales⟧],
   ⟦t:fact⟧[⟦flagcol⟧] = ⟦v:flagval⟧,
   ⟦t:dim⟧[⟦dimcol⟧] >= 2)

Format

Click the measure → Measure tools → Format → Currency $ / Percentage, decimals. On cards: Format → Callout value → Display units: Millions (or Thousands).

Visuals

When: once the measures exist. Build all the visuals for the 4 topics first; formatting comes later.

The three mistakes that always happen

1 · TOP N. Filters on this visual → click the field (the text one: product, country…) → Filter type Top N → Top 10 → By value: drag the MEASURE → Apply filter.

If you drag the text field into By value it ranks by "First" and comes out wrong.

2 · INVISIBLE SECONDARY AXIS. Format → Secondary y-axis → expand → Values → On. Without this the % line is squashed flat on the floor.

3 · SORTING. Three dots (…) → Sort by → choose the field → open it again → Sort ascending/descending. It takes TWO passes. For chronological order pick the AXIS field, not the measure.

Slicer zone

  • Narrow column on the left with 2–3 slicers and a background rectangle.
  • Style: Vertical list / Dropdown (many values) / Tile.

Page navigation

Insert → Buttons → Navigator → Page navigator. It updates itself when you add pages. Copy it with Ctrl+C / Ctrl+V to the other page.

Bookmarks (asked for in Mock 1)

  1. View → Bookmarks (and View → Selection to hide/show visuals).
  2. Set the page the way you want it (filters, visible visual).
  3. Add → rename with a double-click.
  4. Three dots on the bookmark → tick/untick Data, Display, Current page.
  5. Insert → Buttons → Blank → Format → Action → Type: Bookmark → choose the bookmark.
Typical use: two bookmarks that toggle two overlapping visuals (in Selection hide one, save a bookmark; hide the other, save the second). Untick Data if you do not want the bookmark to reset the slicers. In Desktop, buttons are tested with Ctrl+click.

Cleaning

  • Nulls: customer_rating 15%, discount_pct 12%, payment_method and customer_country 1%.

Step by step in Power Query

  1. The 12 months are COLUMNS (2025-01 … 2025-12). In actuals: select cost_center_code, cost_category, currency, currency_rate_to_usd → right-click → Unpivot Other Columns.
  2. Rename Attribute → Reporting Date, Value → amount.
  3. Reporting Date is TEXT "2025-01" → Custom Column with the formula below → Date type. Without this CALENDARAUTO fails.
  4. To USD: Custom Column amount × currency_rate_to_usd → Decimal Number → rename Actuals ($).
  5. Repeat 1–4 in budget → Budget ($).
  6. Expenses table: Merge Queries as New (actuals on top, budget below) on cost_center_code + cost_category + Reporting Date (Ctrl for several columns, same order) → Left Outer → expand only Budget ($) without prefix.
  7. Final columns: Cost Centre Code, Cost Category, Reporting Date, Actuals ($), Budget ($).
  8. Enable load off on actuals and budget.
Date.FromText([Reporting Date] & "-01")

Key measures and status column

Total Actuals = SUM(Expenses[Actuals ($)])
Total Budget = SUM(Expenses[Budget ($)])
Variance = [Total Actuals] - [Total Budget]
Variance % = DIVIDE([Variance], [Total Budget])

Status column in Power Query: first the Variance column (Decimal Number), then Status (Text).

[#"Actuals ($)"] - [#"Budget ($)"]
if [Variance] < 0 then "Miss" else "Meet"
Names with symbols such as Actuals ($) are written in M as [#"Actuals ($)"]. Double-clicking the column list inserts it correctly. If Budget is null, Variance is null and the if errors: use the "with nulls" version in New columns.

  2. What the governance score shows → Variance % by score.
  3. Variance by region and country → bars / matrix / filled map from cost_center_lookup.
  4. Deep dive on one cost centre → slicer or filter + cards + table.

Shortcuts that save time

  • Ctrl+C / Ctrl+V on a visual → duplicates it with all its formatting and filters.
  • Format painter (Home) → copies formatting from one visual to another.
  • View → Selection → select covered visuals and reorder layers.
  • View → Column quality / Column distribution in Power Query → see nulls and errors at a glance.
  • File → Options → Current File → Data Load → untick Auto date/time (at the end, once you use your own Date table).

If something breaks and time is short

Make sure everything is present, even unpolished. A missing part scores zero; a part that is there with a default title scores almost everything.
